# Draft intervention — Dify #42889

Current-main observation:

The 8 KiB issue is path-dependent rather than a failed Skill download.

- `RunConfigSkillsPull` reads the full local `SKILL.md`.
- prompt-mentioned skills are eagerly loaded through `DifyConfigLayer._run_mentioned_pull()` and the internal complete-output path (1 MiB cap), so their `skill_md` can be injected whole.
- agent-driven reads through ordinary `shell_run` still go through `render_prompt_observation_from_result(... edge_bytes=4096)`, producing head + tail only.

That means the same Skill can have different model-visible semantics depending on the access path.

Suggested issue comment:

I think this is better treated as a **complete-read contract** problem than as a request to increase the global shell cap.

On current main, prompt-mentioned skills already have a different path: `DifyConfigLayer._run_mentioned_pull()` calls the internal complete-output runner (up to 1 MiB) and parses `skill_md` directly. The truncation happens when the agent later reaches the same file through ordinary `shell_run`, where `render_prompt_observation_from_result()` always applies the 4 KiB head + 4 KiB tail budget.

So today the same `SKILL.md` can be semantically complete or incomplete depending on *how* it was reached.

A regression test I would add is an ~11 KiB skill with one mandatory instruction only in the middle:

- full/eager path must expose the marker;
- ordinary bounded shell observation currently does not;
- whatever replacement path we choose must allow the agent to deterministically recover the missing range before treating the Skill as read.

I would prefer one of these over simply raising `_SHELL_OUTPUT_PROMPT_EDGE_BYTES`:

1. a dedicated/paginated Skill read API/tool (`offset/limit` or section range);
2. a generic bounded file-read tool with explicit continuation metadata;
3. at minimum, a mandatory continuation contract when an instruction file is truncated.

The important invariant is: **tool success / source selected must not be treated as semantic completeness**.

I have a tiny fixture for the “decisive instruction in the hidden middle” case if useful for a regression test.
