# Full-Coverage Overflow Strategy

ContextMesh does **not** pretend that a corpus larger than a model's maximum context can be placed into one Transformer forward pass.

The contract is instead:

> Every required source block is inspected by the evaluator, no block is excluded by top-k retrieval, model-facing state remains bounded, and every reduced finding remains traceable to the raw source.


## Three gates before a score can exist

v0.8 separates completeness into independent layers:

```text
source files
   |
   +--> Ingest Coverage: was every submitted file parsed/accounted for?
   |
   +--> Semantic Coverage: are every known text/table/visual/media channels addressable?
   |
   +--> Execution Coverage: did the selected judge route actually inspect every required block?
   |
   v
final score unlocked only when all pass
```

This prevents three common false positives: an empty scan producing zero blocks, a visual placeholder being counted as content, and a text-only model being credited with reading an image/audio/video block.

## One external request, many internal reads

The caller submits once:

```json
POST /api/evaluation-jobs
{
  "corpus_id": "corp_xxx",
  "question": "...",
  "answer": "...",
  "route_id": "local-qwen"
}
```

The runtime executes internally:

```text
question + answer
      |
      v
coverage manifest (N required blocks)
      |
      v
priority scheduler   <- BM25/vector ranking may reorder only
      |
      v
ALL N blocks inspected
      |
      +--> raw evidence ledger + provenance
      |
      v
bounded hierarchical reduction
      |
      v
final judge
```

The browser receives progress over SSE. The caller does not need to loop through chunks.

## Why this is different from RAG

RAG normally uses ranking as a gate:

```text
rank -> top-k -> model
```

ContextMesh uses ranking only as a scheduler:

```text
rank -> read these first -> then read every remaining required block
```

The final score is locked while coverage is below 100%.

## Slice-boundary protection

Each required block is the coverage unit. For model backends that support it, ContextMesh adds a small previous/next neighbor window to the inspection prompt:

```text
previous tail
CURRENT BLOCK  <- only this block counts toward coverage
next head
```

This helps preserve cross-boundary references, exceptions and table/header relationships without counting duplicate neighbor text as additional coverage.

## Bounded state, not summary-only memory

Raw corpus and raw evidence stay outside the model window. The model sees bounded state generated by a deterministic reduction tree. Reduction prompts are instructed to preserve:

- contradictions
- exceptions and negation
- dates and temporal changes
- numbers and units
- source block identifiers
- evidence that can change the score

The raw source is never replaced by the reduced state; it can be re-read by block ID.

## What cannot be guaranteed

No generic system can guarantee that a 5M-token corpus evaluated through multiple model calls is mathematically identical to one hypothetical 5M-token full-attention forward pass. If the model's physical context window is smaller than the corpus, that forward pass does not exist.

ContextMesh therefore treats score preservation as an empirical release criterion:

```text
small calibration corpus that fits directly
        |
        +--> direct full-context score
        |
        +--> progressive full-coverage score
        |
        v
absolute drift <= configured tolerance
```

Use this benchmark to validate chunk size, neighbor window, reduction fan-in, prompts and model changes.

## KV / LMCache role

KV caching is an accelerator, not the overflow mechanism.

- It can avoid repeating expensive prefill for contexts already processed by the same compatible model/runtime.
- It does not increase the model's mathematical attention window.
- ContextMesh keeps the portable corpus model-agnostic and treats KV as a disposable model-specific compiled cache.

## Direct-fit vs overflow mode

```text
corpus fits model window?
  |
  +-- yes -> optional direct call / direct benchmark / prefix cache
  |
  +-- no  -> full-coverage external execution
              exhaustive map
              deterministic merge
              hierarchical reduce
              final judge
```


## Capability preflight

Before a full-coverage job begins, ContextMesh checks every required block against the selected judge route. A route that cannot inspect one or more required modalities is rejected before the first expensive model call. This is separate from ingest/semantic readiness: a raw video can be perfectly addressable while a text-only judge is still ineligible to score that corpus.

## Cross-modal and explicit-reference context

Coverage remains block-based, but an inspection may receive bounded context from structurally related source regions: same PDF page, same PPT slide, same sheet/timeline region, immediate neighbors, and explicit `page N` / `slide N` / `sheet X` references. Related blocks remain required in their own right; this mechanism reduces boundary loss without turning relation expansion into a hidden Top-K filter.
